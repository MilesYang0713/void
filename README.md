# VOID v0.17.0 — 不可覆盖的成长时间线

## v0.17.0 修订机制

成长记录现在采用不可覆盖的时间线：

- 点击旧记录的「修订」，不会修改旧节点。
- 保存后会在当前时间新增一条「修订记录」。
- 新节点会保留修改前内容，可展开对照。
- 原记录、修订时间和修订后的内容都会进入本地保存、云同步、JSON、云端备份与 Word 导出。
- 如果新内容与旧内容相同，不会创建无意义的修订节点。

这意味着十天前写下的内容会保持十天前的原貌，今天的变化会作为今天的新事件出现。


本版保留 v0.16.0 的全部灵感成长记录功能，并优化右侧收起栏的可见性与动态提示。


## v0.16.1 小改动

- 右侧收起箭头改为三段式转向灯脉冲，光效会沿展开方向连续推进。
- 增加类似跑道灯的纵向扫描光带与虚线引导灯。
- 默认状态提高亮度与边框对比度，不再融入黑色背景。
- 悬停或展开时增强紫色光晕；系统开启“减少动态效果”时自动停止脉冲动画。

## v0.16.0 功能

- 每颗球均可记录：最初灵感、后续补充、新的推论、待解决问题、下一步行动。
- 新建球时，简介自动成为第一条“最初灵感”。旧版数据首次读取时也会自动迁移。
- 记录自动保存日期和时间，可编辑、删除。
- 下一步行动可标记完成。
- 任意非初始记录可转化为该球下面的新分支。
- 主体球额外提供“整个主题动态”，汇总全部后代最近的成长记录。
- Word 导出会把成长记录写入对应标题下面。
- 成长记录继续随 IndexedDB、Supabase、JSON 和云端历史备份保存。

## 运行

依赖未变化，覆盖旧项目后执行：

```powershell
npm run dev
```

全新目录首次运行：

```powershell
npm install
npm run dev
```

无需重新运行 Supabase SQL。


## v0.17.0 启动稳定性修复

- 移除开发模式下会重复挂载整个应用的 React StrictMode。
- 去重 Supabase 会话恢复事件，避免同一登录状态重复初始化。
- 同一用户的数据启动流程只允许一个实例运行。
- 过期的异步加载结果不会再覆盖较新的状态。
- 已加载的宇宙不会因重复 Auth 事件被切回全屏加载页。


## v0.17.0 — 版本演化日志

设置中新增“版本演化”时间轴。每个节点可以记录版本或阶段、为什么更改、改成了什么，以及实际结果与下一步。记录会随 IndexedDB、本地 JSON、Supabase 云同步和云端历史备份一起保存。旧账户首次打开时会自动获得一条早期阶段回顾和 v0.17.0 节点，不需要重新运行 Supabase SQL。
